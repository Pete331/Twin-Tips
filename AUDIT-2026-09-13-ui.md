# Twin Tips — UI/UX review, 13 September 2026

Prompted by the margin inputs on the tips page overlapping by 5px. That bug was
found by measuring rather than looking, so this review works the same way: an
auditor injected into the running app, walked across every reachable route at
two viewport widths, measuring rather than eyeballing.

## Method

- **Live app**, dev server, signed in, time travel set to 18 March 2026 so the
  season is mid-round and tipping is open — several of these pages show nothing
  in the off-season.
- **Every reachable route**: `/login`, `/register`, `/forgot`, `/rulespage`,
  `/contact`, a 404, `/home`, `/tipspage`, `/leaderboard`, `/settings`.
- **Two widths**: 736px and 375px (iPhone-class).
- **Measured, not judged**: element rectangles, computed styles, resolved
  contrast ratios, accessible names, target sizes, heading order, document
  overflow, landmarks.
- Source read afterwards to confirm each cause.

**Two false positives were found and excluded**, because a review that reports
noise is worse than a shorter one:

- `MuiSelect-nativeInput` — MUI's own hidden input behind every Select. It has a
  21px box and no name, and it is not a target anybody hits.
- The header logo link, reported as unnamed because the checker did not read
  descendant `alt` text. It wraps `<img alt="Twin Tips">` and is named correctly.

## What is already right

Worth stating, because these are the things that usually go wrong:

- **No horizontal overflow at 375px on any page.** Not one.
- **No contrast failures anywhere.** Every element holding its own text was
  measured against its resolved background: nothing fell under 4.5:1, or 3:1 for
  large text. (Limited to solid backgrounds and direct text nodes.)
- **Landmarks are correct** — exactly one each of `main`, `header`, `footer`,
  `nav`, on every page.
- `lang="en"` is set. No duplicate element IDs. No `target="_blank"` without
  `rel="noopener"`. No image missing an `alt` attribute.

---

## 1. Every navigation item is a `<button>` inside an `<a>` — high

`components/Navbar/AppBarCollapse.jsx:106` and `components/BottomNav/index.jsx`:

```jsx
<Link key={link.to} to={link.to}>
  <Button ...>{link.label}</Button>
</Link>
```

which renders `<a href="/Home"><button>Home</button></a>`.

- **Invalid HTML.** An `<a>` may not contain interactive content.
- **Announced twice.** A screen reader meets a link called "Home", then a button
  called "Home" inside it. Every nav item, on every page. This alone produced
  3–4 duplicate accessible names per page in the audit.
- The header's help icon three lines earlier already does it correctly:
  `<IconButton component={Link} to="/rulespage">`. So the file disagrees with
  itself.

**Fix:** `<Button component={Link} to={...}>` — MUI renders a single `<a>`
styled as a button. Same for `BottomNavigationAction`, which takes `component`
too.

## 2. Navigation points at URLs the routes do not declare — medium

`AppBarCollapse.jsx:26-28` and `BottomNav/index.jsx:33-35` link to `/Home`,
`/TipsPage`, `/Leaderboard`, and `/Settings`. Every route in `App/index.jsx` is
lowercase, and so is every other link in the app — the logo goes to `/home`, the
home page's league rows to `/leaderboard?league=...`.

React Router matches case-insensitively, so it works. The cost is that **one
page has two URLs**: click the logo and the bar reads `/home`, click Home in the
nav and it reads `/Home`. Browser history and bookmarks collect both, and the
day anyone turns on `caseSensitive` or moves router, the nav breaks.

**Fix:** lowercase those four entries. Nothing else changes.

## 3. Every page is titled "Twin Tips" — medium

`document.title` never changes. Measured on `/home` and `/leaderboard`:
identical.

- Ten open tabs are indistinguishable.
- Browser history and bookmarks are a list of the same word.
- A screen reader announces the title on navigation, so **moving between pages
  is not announced at all** — which matters more in a single-page app, where
  there is no page load to notice.

**Fix:** set the title per route. The season context already knows the round, so
"Round 12 tips · Twin Tips" is available cheaply.

## 4. Standalone links are below the minimum target size — medium

WCAG 2.2 SC 2.5.8 (AA) asks for 24×24 CSS px. Measured at 375px:

| Page | Link | Size |
|---|---|---|
| `/login` | Forgot password? | 114×**17** |
| `/login` | Don't have an account? Register | 203×**17** |
| `/login` | Still can't sign in? Contact us | 182×**17** |
| `/forgot` | Just remembered? Login | 158×**17** |
| `/register` | Already have an account? | 201×**17** |
| `/home` | each league name in the table | ~×**17** |

These sit on their own rows, so the SC's exception for text inline in a sentence
does not apply. Three of them are stacked directly under one another on the
login page — small targets close together, which is the combination that causes
mis-taps.

**Not a failure:** the footer's "Twin Tips" and "Contact us" at 70×19 and 78×19.
They *are* inline in a sentence, so the exception covers them.

**Fix:** vertical padding on the stacked links (`py: 1` takes 17px to ~33px)
without changing how they look.

## 5. No skip link — medium

Nothing lets a keyboard user jump past the header. On every page they tab the
logo, three nav items, help and the account menu before reaching content.

Landmarks are correct, which gives screen-reader users a way around it. Keyboard
users without a screen reader have none.

**Fix:** one visually-hidden anchor to `#main`, revealed on focus.

## 6. Nine legacy `align` attributes remain on the tips page — low

`align` on a `<div>` is a presentational attribute from HTML 4 that modern
browsers still honour (computed `text-align: -webkit-right`). It is the same
class of thing already removed from the Squiggle image and two grid cells.

**Fix:** `sx={{ textAlign: "right" }}`.

## 7. Heading levels jump h1 → h3 on the tips page — low

There is no h2 between them. Screen-reader users navigating by heading meet a
gap and cannot tell whether they missed something.

## 8. Two settings cards do the same job differently — low, design

- **Change username**: field, then Save below it, disabled until something is
  typed.
- **Change favourite team**: select with Save *beside* it, enabled before
  anything has changed.

Adjacent cards, same job, two layouts and two rules about when Save is live.
Pick one — the disabled-until-changed pattern is the better of the two, because
it says whether there is anything to save.

## 9. A signed-in user visiting /login gets the login form — low

The header shows their avatar and the bottom bar shows Home / Tip now /
Leaderboard, while the page asks them to sign in. `/login` should send an
authenticated visitor to `/home`, the way the footer's logo link already
decides where to point.

---

## Suggested order

1. **Nav markup** (#1) — one pattern change in two files, removes the largest
   accessibility fault and the duplicate-name noise with it.
2. **Link casing** (#2) and **page titles** (#3) — both small, both affect every
   page.
3. **Target sizes** (#4) and the **skip link** (#5).
4. The rest as housekeeping.

None of this is a rewrite. The layout, the spacing, the colour and the
responsive behaviour are in good shape — the measured results say so. What is
left is markup correctness and the details that only show up on a phone or
through a keyboard.
